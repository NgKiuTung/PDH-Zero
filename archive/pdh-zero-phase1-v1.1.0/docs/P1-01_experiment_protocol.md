# P1-01 第一阶段实验协议

## 1. 研究设计

第一阶段是工程与研究可行性实验，不用于直接证明论文主创新。所有实验按 Gate A → Gate B → Gate C 顺序执行；上一门禁未通过时，停止消耗下一门禁的 GPU 额度。

## 2. 资源预算

| 环境 | Gate A | Gate B | Gate C | 第一阶段上限 |
|---|---:|---:|---:|---:|
| RTX 5090 32GB / 14 vCPU | 1.5 小时 | 3 小时 | 1.5 小时 | 6 小时 |
| 本地或临时 CPU | 静态验证与结果分析 | 可选 | 统计 | 不计 GPU 小时 |
| 历史 AMD 证据 | 仅作迁移参考 | 不复用为新结果 | 不参与 | 0 小时 |

触及上限前必须生成阶段报告。禁止因一次失败直接重复长任务；先定位错误，再运行最小复现实验。

## 4. 受控变量

同一对照组应固定：

- 规则版本 `mini_pdh_v0`；
- 模型参数量和隐藏维度；
- 训练环境步数；
- 优化器与学习率；
- 评估牌墙种子；
- 四座位轮换方式；
- 对手组成；
- Torch 精度；
- 同一云实例类型。

## 5. PPO 自博弈边界

四个风位共享 Actor 参数，但不能把四家的零和回报直接相加更新同一参数，否则目标的期望和可能退化为常数零。

第一阶段采用：

1. 每局随机选择一个学习者风位；
2. 当前策略仅从该风位的轨迹更新；
3. 其余三家由冻结策略、随机机器人或启发式机器人控制；
4. 冻结策略按固定更新周期同步；
5. 通过风位随机化让同一 Actor 学习四个位置。

这是第一阶段的训练闭环设计，不是最终联赛算法。

## 6. 奖励

Mini-PDH 使用严格零和终局结算：

- 自摸：赢家 `+3m`，三家各 `-m`；
- 点炮：赢家 `+3m`，放铳者 `-3m`，其他两家 `0`；
- 流局：四家 `0`。

`m` 是 Mini-PDH 牌型最高倍数。训练可将原始净分除以固定常数做数值缩放，但禁止裁剪为 `-1/0/+1`。日志必须同时保留原始净分。

## 7. 统计

第一阶段不作论文级显著性结论，但至少要求：

- 3 个训练种子；
- 每个评估牌墙进行四次风位轮换；
- 最少 5,000 个牌墙种子；
- 报告均值、中位数、标准差和 95% Bootstrap 区间；
- 报告每个风位结果，不只报告总均值；
- 保留失败种子，不得删除后再计算。
