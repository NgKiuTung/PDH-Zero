# P1-00 第一阶段范围与冻结边界

## 1. 阶段目标

第一阶段回答三个问题：

1. 当前 RTX 5090 CUDA 环境能否稳定运行研究代码，并保留 CPU/ROCm 兼容路径；
2. 一个缩小但仍保留四人、隐藏信息、碰牌与大胡约束的环境能否完成从零学习闭环；
3. 当前 1×RTX 5090、14 vCPU、60GB 内存的共置实例是否足以进入 Full-PDH 和 RGRC。

## 2. 最终消费者

| 交付内容 | 消费者 | 用途 |
|---|---|---|
| 环境验收证据 | 研究负责人、后续开发者 | 判断云资源是否可作为正式实验平台 |
| Mini-PDH 代码与回放 | 算法开发者、复现者 | 验证状态机、观察边界和训练闭环 |
| 吞吐报告 | 研究负责人 | 决定第二阶段模型规模、引擎语言和算力预算 |
| 操作手册 | 实验执行者 | 在没有聊天上下文时独立完成实验 |

## 3. 本阶段必须完成

- A00 CUDA 版本、Compute Capability 与 `sm_120` Kernel 预检；
- A01 系统与硬件盘点；
- A02 PyTorch ROCm/CUDA 前向、反向、优化器；
- A03 CPU 与加速器精度对照；
- A04 Checkpoint 与 RNG 恢复；
- A05 停机重启存储哨兵；
- A06 有界稳定性浸泡；
- B01 Mini-PDH 单元和属性测试；
- B02 随机与启发式机器人基线；
- B03 PPO 自博弈冒烟；
- B04 Privileged Critic 对照；
- B05 Actor 隐藏信息隔离；
- C01 纯环境吞吐；
- C02 策略批推理吞吐；
- C03 端到端训练吞吐与成本外推。

## 4. 本阶段禁止扩展

- 136 张完整规则；
- 码、杠、抢杠、一炮多响、十二张落地承包；
- RGRC、LACC、PICED；
- MCTS、ReBeL、Deep CFR；
- 大规模联赛、五种规则变体；
- 移动端、Web 产品或商业接口；
- 为占满 32GB 显存而扩大模型。

## 5. 阶段结束条件

第一阶段只允许出现四种结论：

- `PASS`：A、B、C 全部通过，可进入 Full-PDH；
- `PASS_WITH_RISKS`：闭环成立，但吞吐或稳定性需要先优化；
- `FAIL`：存在已证实的阻断问题；
- `UNVERIFIED`：缺少实机证据，不能作出通过声明。

未执行 RTX 5090 实机实验时，CUDA/Blackwell 兼容状态必须保持 `UNVERIFIED`。
