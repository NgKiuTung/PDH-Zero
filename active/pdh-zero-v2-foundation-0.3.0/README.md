# PDH-Zero v2：已确认规则基础包

版本：`0.3.0-foundation`。这是独立的CPU参考实现候选包，**不是完整麻将引擎、模型或可训练版本**。未修改旧v1.1.1、旧Checkpoint或云实例。

## 本包能做什么

| 模块 | 实际能力 | 明确不代表 |
|---|---|---|
| `tiles.py` | 136张实体、34种牌、面子和候选胡牌物理张数校验 | 完整发牌、摸补牌顺序 |
| `shapes.py` | 标准四面子一将分解、七对4/8/16/32档、四暗刻10/13结构候选 | 已判出合法大胡或完整叠加总分 |
| `qualifications.py` | 碰杠对必要资格的影响、单纯清/混门清条件、海底摸前阈值 | 完整路线完成概率或Actor |
| `dealer.py` | 首次胡0、连庄递增、流局保留、闲家胡归零、多响下庄选择 | 完整连续对局状态机 |
| `horses.py` | 单赢家三类牌源；多响旧墙不足时专门新牌序；统一马牌逐赢家算m | 尚未确认的物理墙端或随机洗牌实现 |
| `responsibility.py` | 落地展示计数、第四碰责任锁定、同局自摸责任范围 | 杠爆、连续杠和抢杠责任 |
| `settlement.py` | 普通单赢家、多响、第四碰自摸承包、流局零分；倍数不封顶 | 完整牌型F的计算或自动行牌裁决 |
| `ledger.py` | 单赢家、多响、第四碰责任的待结算/绑定/一次付款 | 整个对局或外部真实资金支付 |
| `journal.py` | 规范JSON快照、来源哈希校验、多类账单断点恢复 | 游戏Worker、Actor或PPO恢复 |

`rules/source-v0.8.md`是当前房规语义来源。`rules/cases.json`追踪115条T案例；`KERNEL_COVERED`只表示对应纯函数契约已有测试，不代表完整房规或整局集成已经通过。

## 本轮关键规则

- 一炮多响旧墙足够时共用旧墙；旧墙不足时新开一副牌供所有赢家共用，结算后重新洗牌，重新洗牌不增加连庄。
- 多响不借任何赢家的下一把手牌，不为每个赢家重抽马牌；每位赢家按自己的本局相对位置计算中马数。
- 十二张落地承包只由第四次碰牌触发；第四碰放碰者只承担该碰牌者同一手内自摸的三家份额。
- 三碰后暗杠、明杠或加杠不触发第四碰责任；点炮胡由实际点炮者支付普通一家费用。
- 牌型倍数无封顶；流局零分但保留事件记录。

## 运行CPU验收

```bash
python3 tools/verify.py
```

留存新报告：

```bash
python3 tools/verify.py --report-dir verification/local-run-001
```

报告目录必须不存在。正常输出包含：

```text
foundation_check: PASS
training_ready: false
full_rules_frozen: false
```

退出码0只证明本批CPU基础检查通过。没有训练命令、GPU任务或自动云端升级行为；不要把本包设为`PDH_PHASE1_ROOT`，也不要覆盖现有`env.sh`。

## 输入与恢复契约

固定玩家ID按逆时针0..3，牌实体ID为0..135。公开投影不得泄露未公开实体索引。马牌选择函数只消费调用方已生成并记录的真实顺序，不自行洗牌、排序、重抽或混补。

多响旧墙不足时，`plan_multiwin_horses`固定选择`SEPARATE_DECK`，绑定时要求完整136张专门牌序；该牌序只服务上局结算，之后必须重新洗牌再开打。DealerState只按真实胡牌事件更新一次，专门开马和重洗不会再次增加连庄。

第四碰责任使用`TwelveGroundedLiability`冻结手ID、碰牌者和放碰者。账本只在同一手、同一碰牌者自摸时执行三家承包；点炮胡仍走普通点炮。快照恢复后重复支付返回原收据，不重复累计。

## 重要边界

严格ruff/mypy仍未在当前离线环境执行；完整P0规则封板继续等待`rules/open_decisions.json`。尚无完整`env.step`、完整评分器、全局牌谱投影、批量Actor、Critic、PPO、Worker或长任务启动器。`training_ready=false`和`full_rules_frozen=false`必须保持。
