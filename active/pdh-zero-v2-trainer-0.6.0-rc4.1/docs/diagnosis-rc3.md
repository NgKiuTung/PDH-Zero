# rc2结果与rc3变更依据

## 已有证据

用户rc2日志：37次接受更新、754462学习者决策、4839.33秒，总门禁INCONCLUSIVE。
同一重复开发集1024手：baseline均分−0.1230；265k为+0.4082；509k为+0.2480；
754k为−0.0410。所有净分差置信区间跨0。末次点炮率有所改善，但CVaR点估计更差。
这些数据不证明265k是普遍最佳停止点，也不证明累计KL是尾部变差的原因。

实际代码问题：rc2只在PASS时替换best，每次更新覆盖latest；三个开发点均为
INCONCLUSIVE，因此没有永久保存265k/509k权重。rc3修复存档，不声称补回已丢权重。

## 最小变更

保留384宽度和现有合法多路线特征；保持SOLO和真实净分奖励。
增加完整批次累计anchor约束及有界调节，防止只检查单步KL；不把某个KL数值等同于策略坏。
每个候选都保存；开发选择、统计资格、最后更新分别表示。CVaR按牌墙组配对计算。
逐笔付款对账，区分事件责任与马放大；不能从−125一个数字推断谁包赔。
共享数值缓冲减少大Python对象传输，但仍为同步采样，尚未证明目标5090提速。

## 不实施的猜测性改变

不重新扩大网络、不强制更少碰杠、不把胜率变成主奖励、不重启DUO，
不把没有独立校准的风险头接回Actor，不以INCONCLUSIVE自动判定失效或有效。
未引入候选弃牌全信息hazard训练；先保持隔离，避免再把多个算法变动混在同一次调优。
