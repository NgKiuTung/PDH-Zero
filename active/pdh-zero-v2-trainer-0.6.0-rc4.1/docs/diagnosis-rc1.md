# rc1诊断：实现事实与未证实因果

依据：用户停止日志 `貼上的文字 (1)(5).txt` 和原rc1源码。
日志SHA256见 `verification/rc2/rc1-audit.json`。旧实验文件未修改。

## 可以确认

1. 本轮人工Ctrl+C导致KeyboardInterrupt，旧程序将它标failed。GPU进程已退出；
   warmup和latest均存在。warmup没有遗失，不必重复17分钟教师生成/克隆。
2. 原`risk_pair(pair)`使用共享观察编码器。仅对risk_logits在Actor评分中detach，
   不会阻止BCE沿risk_pair输入反向改变编码器。本地三个独立风险更新确实改变共享参数。
   新回归测试证明风险监督不再改变Actor编码器或logits。
3. update10切课程的同时执行了突发教师复习；update11 KL约0.028并发生碰牌频率变化。
   两种变化重叠，无法仅凭聚合日志把退化因果唯一归给DUO。
4. 旧learner点炮率以桌数为分母。update14有384桌，但有206+178×2=562个学习座位-局。
   41次点炮/384=10.68%是每桌口径；每学习座位-局是41/562=7.30%。
   SOLO与DUO不能不改分母就直接比较“点炮几乎翻倍”。
5. 旧risk_samples和risk_positives是按PPO遍历累计，不是独立数据集规模。
   新版分别报告唯一选中弃牌、正例与优化器尝试步数。
6. 初评与504578决策的聚合均分差为-0.0986，点炮率反而略下降。
   仅聚合均值不足以做成对显著性判断，不能直接宣称因果性“训练彻底坏了”。

## 本次受控干预

固定SOLO；复用warmup权重但重置优化器；risk仅诊断并重新建立新基线；
冻结warmup KL锚、较小学习率、完整批次KL回滚、取消突发BC。
这是一组稳定性修订，不是已经证实每一项都提高收益的消融结论。

## 仍不确定

本地没有用户真实checkpoint_warmup.pt及逐局评估，不能直接复算旧模型决策，
也不能保证新策略已经更强。目标GPU吞吐和策略结果必须由新同条件实机实验提供。
合法胡牌捕获高不等于全局策略优秀；lower risk loss不等于校准或防守成功；
CPU时间增加不等于训练有用；0%瞬时GPU利用率也不等于进程未工作。
