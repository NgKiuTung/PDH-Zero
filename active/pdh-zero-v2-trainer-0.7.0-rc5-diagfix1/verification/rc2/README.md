# 0.6.0-rc2 实际验证记录

环境：Python 3.13.5、PyTorch 2.10.0+cpu，CUDA不可用；cgroup约4核等效。
这些是本地程序验收，不是用户RTX 5090上的效果或吞吐验收。

## 最终采用的结果

- 全部264项测试通过，警告作为错误；`final-tests.log`为无插桩回归。
- 最终coverage插桩全套264项通过：`coverage-supervised-tests.log`。
- 源码行覆盖87.76%，含分支综合84.39%；新增12个核心模块行覆盖83.39%，综合78.77%。
  子进程worker的内部覆盖未启用子进程追踪，父进程coverage不能证明那些分支全覆盖。
- 108个Python文件通过3.10 AST解析；实际运行并非Python3.10。
- 基础静态检查PASS，0个硬错误，84条软复杂度提示；ruff/mypy没有安装，NOT_RUN。
- 真实CLI SIGINT测试：退出码0、manifest=stopped、signal_2，3个登记子进程全部退出。
- 串行、2worker、4worker的同32手共9433动作，最终摘要完全一致。
  采样段吞吐2760→4167动作/秒，约1.51倍。计入进程启动/退出则3.42→4.72秒，
  这个极短试验并未获得端到端加速。不得宣传2倍或GPU利用率达到某数值。
- 风险梯度红例：旧实现只做3次风险监督，共享Actor权重变化约0.001603；新版回归要求
  同样的风险监督下Actor编码器和logits不变，风险头自身更新。

## 文件说明

`rc1-audit.json`含原日志哈希和旧指标分母复算；`benchmark.json`包含完整计时口径；
`cli-interrupt.json`包含实际PID回收检查；`coverage*.json`含详细覆盖。
`baseline-tests.log`是原233项基线；早期带失败的日志保留为迭代过程证据，不作为最终通过报告。
早期coverage运行曾因外层命令超时影响旧长任务测试；最终以独立受控进程完成全套插桩验收。
旧极小长任务测试的时间上限改为180秒以容纳插桩；生产训练预算不变。
