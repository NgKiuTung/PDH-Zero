# PDH-Zero v2：模型与整体实验重建蓝图

版本：设计审阅 v0.1  
日期：2026-09-30  
消费者：研究负责人、规则确认者、规则引擎开发者、训练与评估执行者、复现审核者。  
状态：设计已整理；尚未实施 v2、尚未训练新模型、尚未批准云算力开销。所有配置范围是待基准验证的设计候选，不是实测最佳值。

## 1. 决策与研究目标

建议正式模型在新房规下从随机初始化重新训练，复用经核对的工程工具，不延续旧 Mini-PDH 的策略结论。不删除旧代码、模型和实验。

目标保持为无真人牌谱训练：四名玩家依据各自手牌与合法公开信息行动，通过四人自博弈学习纯大胡的动态做牌、碰杠取舍、进攻与防守。规则生成的监督标签和自博弈产生的牌谱均属于新生成数据，不属于真人示范；它们的来源需在论文中分别披露。

建议最终目标为连续对局累计净分，并以每实际对局平均净分及尾部损失报告效果。单局受控评估作为诊断，不冒充连续玩法。训练窗口长度、折扣时钟和评估会话终止方式属于实验协议，需要在正式训练前确认；不借此改动实际房规。

### 1.1 从头开始的范围

## 2. 本轮只读核对的发现

本轮读取了房规 v0.6、v1.1.1 代码包和 B06 分析包；没有操作云实例。源码路径均相对于旧包 `pdh-zero-phase1-v1.1.1/`。

| 发现 | 证据位置 | 对 v2 的要求 |
|---|---|---|
| 一次采样只收集一个轮换学习座位；其余是冻结或规则对手 | `src/pdh_phase1/rl/self_play.py:43-75, 103-115` | 真正四家当前策略对打时，四家分别收集学习轨迹；历史对手行动不伪装成当前策略样本 |
| 一桌结束才开下一桌，单次推理为一个局面 | `self_play.py:61-105`；`rl/model.py:98-110` | 多桌环境推进与GPU推理合批 |
| 每动作有 `.item()` 标量回传 | `rl/model.py:105-111, 122-129` | 每个推理批次统一回传，避免重复细粒度同步 |
| 训练局数是64条非空学习者轨迹，不是所有尝试对局 | `self_play.py:107-132` | 零动作座位不产生策略梯度，但实际对局与全部座位结果必须入账；全部对局统计与可训练序列统计分开 |
| 环境决策数包括整桌四家动作 | `self_play.py:105-106, 128` | 同时报告全桌动作数、当前策略有效决策数与优化器更新数 |
| `update_seconds` 包含采样耗时 | `rl/trainer.py:109-140` | 改为互斥计时：环境、推理、传输、PPO、写盘、评估；不能直接相加旧两个字段 |
| 原观察以牌数直方图为主 | `mini_pdh/observation.py:47-70` | 新编码包含公开事件顺序、杠来源、跨局状态与亮马留手信息 |
| 最终评估仅返回聚合值 | `evaluation.py:29-69` | 保存逐局结果和可重放行动，再从同一事实源派生指标 |
| 相同受控牌墙四座位评估存在，但基线条件不完整 | `evaluation.py:73-104`；旧 `rule_baselines.json` | 增加候选启发式对相同三家启发式、固定对手池与交叉对战 |

重新计算的旧实验规模：六组各3540次更新、226560条非空学习者轨迹；实际尝试对局每组231687～231979局。旧 `environment_decisions` 合计25413916，不能称为同样多的有效学习者决策。

六组采样耗时占原更新循环时间的88.43%～88.64%。该字段包含环境、逐局推理等开销，不能仅凭它断言88%全部是纯Python环境计算。旧循环统计约937.78个全桌决策/训练秒；此值只作旧环境基线，不能用于承诺136张新环境吞吐。

## 3. 房规完成度与启动门禁

v0.6已明确多项关键机制：门清限定、牌型去重叠加、四暗刻10/13、幺九系列、海底摸前阈值、按上局相对庄位计马、连庄与流局、三种马牌来源、跨局亮中马且留手。具体语义只引用原文，不在本文件重定义。

仍未封板的事项见原稿第9节：Q1幺九分类边界，Q3四喜及字牌交叉，Q4其余七对花色组合，Q5十三幺及过胡，Q6多解释选择，Q10c发牌/摸补牌方向，Q10d超出单副牌容量，Q11多响，Q12承包/抢杠范围/流局付款/封顶，Q13散场待结算。

### 3.1 实施与训练分开

可以先设计并实现已确认规则的纯函数、事件与账本结构、录谱、状态隔离和批量接口；不需要因为一个未决条目停止所有互不依赖的工程。

但正式整局自博弈配置在上述会影响可达状态、合法动作、计分和终止的条目未明确前不得标记为冻结。不得把未知分支静默设为关、不计分、弃局或重新发牌；不得过滤遇到未决事件的局来声称已验证完整房规。运行时意外命中未知规则应保留现场并停止该正式实验。

建议先集中确认最影响防守和结算的一组：一炮多响是否启用及下庄顺序、承包责任者/触发/份数、封顶与流局付款。随后一次确认其他牌型交叉和摸补牌物理顺序。不再重复询问已闭合的抓马三个分支。

## 4. 系统结构：一套完整136张规则，两个时间尺度

### 4.1 单手状态与跨手会话状态

单手状态记录136张实体牌、原始墙序、发牌顺序、手牌/副露/牌河、摸补牌锚点、响应窗口、最后胡牌张及胡前结构。规则只能操作真实存在且位置一致的实体牌。

会话状态记录固定玩家身份、当前庄家、相对庄位、该任庄家是否首次胡过、累计连庄、待结算单、结算牌源、下一局实际发牌和已公开留手牌。换庄不交换玩家身份，专门开马/重新洗牌不伪造实际对局或连庄事件。

胡牌成立、金额结清、下一把发牌是不同事件。跨局借马时，先保存上一手结算快照，在规则允许的新局发牌发生后读来源，再给上一手账本付款。不会把未知m当零，或把付款错计为下一手的胜利。

### 4.2 参考规则与性能实现

先以清晰、可审阅的Python参考实现建立规则验收；多进程批量采样不要求一开始重写两套完整引擎。性能剖析若证实胡形分解、合法动作或环境推进为主瓶颈，再将确定的热路径迁移Rust，并用同一牌例和事件流差分验证。Python与Rust不维护两套独立房规目录。

不为了模型容易学习而再次造简化计分牌型或取消碰杠/抓马。极小局面仅用于单元测试，不能作为正式136张训练环境的替代。

### 4.3 隐藏信息边界

审计真值可以保存所有手牌、墙序和抽马序列；Actor只能读取自己的手牌及截至该时刻实际公开的信息。

特别处理跨局中马留手：下一手对手确实知道已亮命中牌的种类、数量和持有人，未亮牌身份仍隐藏。公开副露、公开但留手的牌、已弃牌分开建模，不重复计牌。若公开的候选张数和命中数量使未亮部分存在可推导的类别约束，允许表达这种约束，不泄露其具体身份或未公开实体位置。

规则服务器可以在私有状态计算谁能胡/碰，但未公开响应窗口和他家动作合法集合不能经诊断字段或调度信息泄漏给Actor。一次胡牌尚未发生时，策略不能看到未来中马数、未来洗牌结果或下一手手牌。

## 5. 模型候选：共享策略、独立记忆、多路线与风险辅助

### 5.1 保留小型专用策略网络

第一版采用牌状态编码器、公开事件序列编码器、GRU记忆和合法动作评分头，初始隐藏宽度候选为256。参数量由真实实现报告，不先承诺千万级，也不为占用32GB显存强行扩大网络。

牌状态使用34种牌的计数与身份特征；事件编码保留行动顺序、来源、胡牌前结构所需历史、杠类型及公开亮马。输入同时包含当前相对庄位、连庄、剩余牌数、门清附加资格与责任状态。

四个座位共享Actor参数，但各桌各座位有独立的隐藏状态、观察和奖励。回合制依然按规则顺序执行，不能因为“同时训练四风位”而同时打牌。新一手不保留上一手已经无效的私有牌状态；通过显式会话字段及新局公开事件带入真正需要继承的信息。

### 5.2 动作与候选路线结合

合法动作按种类与参数表示：弃哪一种牌、碰、明杠、暗杠、加杠、胡、过；具体许可由规则确定。胡形多解释是否由最高计分自动选择，依Q6，不让模型借任选解释拼接收益。

候选路线不互斥地记录：基础结构、花色条件、暗结构、幺九条件和适用附加项。每条路线区分：规则资格是否仍在、不可行原因、结构距离的定义与精确性、有效进张、根据公开信息得出的未见牌上界、当前已满足的计分条件。

每个候选动作还编码它会取消、保留或改善哪些资格。例如暗杠取消普通清/混门清附加、允许保留四暗刻、破坏七对的未声明四张组；这些是确定的规则特征，不是“碰杠固定扣分”。

路线可行性、距离和预测完成概率必须分字段。未见牌可能在他家手里；不得把未见牌上界写成剩余牌墙张数。没有精确计算的距离应明确为启发式估计，不伪称所有复杂组合都有精确向听数。

策略直接对合法动作评分，不必须先承诺一个目标牌型。所有路线共同影响评分；不奖励路线数量、频繁变牌或机械不碰杠。

### 5.3 Critic与防守辅助

最小基线使用仅凭合法观察历史的价值网络。特权Critic作为受控比较，输入Actor可获得的历史表示与训练时当前潜在状态；不把未来抽马/下局预采样结果作为默认输入，也不把特权网络输出直接传入部署Actor。

特权Critic并不保证更好。部分可观察下只用当前全状态替代历史条件可能存在理论问题；采用历史条件加当前特权信息的设计，并用对照验证，而不是依据旧三种子轻微均值差就默认获益。[R3]

后续候选辅助头：每种弃牌的即时可接炮风险估计、条件点炮损失、终局收入/点炮损失/被自摸损失/承包损失分解，以及路线完成概率。完整训练真值可用于生成标签，但执行期输出仍是从合法观察推断的概率，不是读取对手手牌。

“他人当前能否接炮”和“按对手策略实际是否胡”是不同事件；标签分开，不能把未观察到的反事实动作结果捏造成事实。防守头采用概率校准与收益评估，不仅看分类准确率。

辅助头按增量实验启用，基线和各消融的输入/参数量/样本预算需受控。没有效果的头不保留为必选复杂度。

## 6. 奖励与连续对局训练

主奖励来自已核定的逐玩家真实净分账本。普通点炮一份、自摸三份、承包专项、倍数去重、马和连庄均由规则层产生。四家零和净分不能相加为一个所有人共同最大化的奖励；每个座位使用自己的回报与优势。

不预加每次碰杠惩罚，不额外奖励胡牌次数、门清天数、路线数量或流局。否则会把收益目标改成未确认的风格目标。先报告尾部风险；确需改变风险偏好时另立明示的优化目标和消融，不暗中改变基线奖励。

稀有高倍结果不能随意裁剪成与普通点炮相同的奖励。保留原始积分；数值稳定措施可先用统一正比例缩放和梯度裁剪。可学习价值归一化等措施需单独验证，跨模型比较仍使用原始积分。

### 6.1 待结算不是终止

创建待结算记录后，在规则产生真实马来源前不提前提交该手的终局回报。结算阶段无策略动作时，不因洗牌或等待增加一个虚假的折扣步。产生下一手手牌不意味着这些信息早已可用于上一手决策。

训练采用连续状态流、固定长度学习切片和正确的bootstrap；切片到时不等于牌局流局，换庄也不自动是终止。手内不按算法循环次数额外惩罚慢牌；跨手折扣及会话目标在协议中固定。

单手统计的金额仍归上手；训练序列里的真实到账事件只进入回报一次。不得既回填旧手终局奖励又在下一手到账时重复发奖励。评估窗口结束后的未结账单必须完成或明确记为未完成，不能假装m=0。散场房规见Q13，尚未确认前不选择一个隐藏替代方案。

### 6.2 四家自博弈

初版采用同步采样/更新：一个采样批次内当前策略版本固定，各桌各座位独立记忆。可以同时收集四家当前策略的轨迹；仅含规则/历史对手的桌，只将当前策略控制座位的样本送入当前PPO。

对手池至少包含当前冻结副本、有限历史快照和规则启发式，不只训练针对一个弱对手。初始混合比例先短试并固定为实验配置，不将历史策略数据不加校正地当作当前on-policy样本。不同对手配置和所有随机源独立记录。

如自然开局学习过于稀疏，才评估规则生成的合法近终局课程或牌型辅助监督。课程仍使用同一完整规则，不加入虚假门清胡、不靠偷看牌墙选动作；课程来源与自然局分开统计，最终测试仅按预先声明的自然分布和诊断分布分别报告。课程不是默认附带收益保证。

## 7. RTX 5090单实例吞吐计划

硬件基线来自用户已有验收：RTX 5090 32GB；cgroup CPU上限14个核等效配额，内存60GiB，无swap。仅将其作为已验收实例快照，下一次运行先核对，没有假定换实例后资源相同。

建议起点：8个环境worker，每个16张牌桌，共128桌；一个GPU推理/学习进程与一个分块写盘组件。CPU线程池先限制到不超配，不能按可见128逻辑核开128个worker。

| 变量 | 候选扫描 | 选择依据 |
|---|---|---|
| 环境worker | 4、8、10，必要时12 | 全桌动作/s、cgroup节流、队列等待 |
| 每worker牌桌 | 16、32、64 | 推理聚合大小、时延、内存 |
| 推理batch | 64、128、256、512，必要时1024 | 真实Actor吞吐，必须允许等待超时后发送不足满批的请求 |
| 每PPO批次有效Actor决策 | 16384 → 32768 → 65536 | KL、效果、更新次数与样本效率 |
| 递归序列长度 | 32、64、128；必要的burn-in另记 | 截断记忆误差、padding、显存、吞吐 |
| 精度 | FP32基线；BF16按实际网络复测 | 数值稳定、时间、真实收益，而非只看显存 |

不是全组合穷举。先做单因素短试，再组合少量最佳候选。环境采样与推理异步排队，但PPO第一版保持有界、固定版本批次；不在初版同时引入无界异步学习、搜索和多个独立训练服务。

性能指标：完整牌局/s、全桌决策/s、有效Actor决策/s、GPU推理等待与传输时间、PPO独占更新时间、日志开销、每百万样本耗时。nvidia-smi利用率仅作辅助，不把更大模型、无意义重算或错误经验重复使用当成“push”。[R2,R4]

验收以新规则同任务的串行参考与并行版本比较。内部优化目标先设至少2倍有效采样吞吐，尚未实测，不保证达到；不能拿旧52张玩具环境的937.78决策/s直接宣称136张版本加速比。若无法达到目标，报告剖析并继续定位，不修改房规换取速度。

必须验证批量与单局模式在固定牌墙和指定动作流下状态/账本一致、GRU状态不串桌、随机源不随worker调度串流。确定性回放与统计复现分别说明，不承诺跨任意GPU后端逐位一致。

## 8. 牌谱与数据生命周期

### 8.1 全量与诊断记录

每个真实训练、评估牌局均保存紧凑可重放事件：实际初始牌序、实体ID、发牌、动作、碰杠与来源、结束原因、结算和牌源链接；所有座位结果与无动作座位都记录。

每次实际决策保留行为策略ID、版本、动作、行为概率/对数概率，以及紧凑的路线/风险诊断或可精确重建它们所需输入。派生数据与事实事件分开；不能用一段生成的心理解释取代模型数值。

正式评估保留完整合法观察、合法动作、策略分布与值预测；训练中的完整大张量按固定抽样和异常触发保存。所有局仍必须可重放，不以抽样之名删除非抽样局的动作历史。

### 8.2 归档原则

原始事件是事实唯一来源；终局表、牌路摘要和图表是可再生成视图。分片压缩写入，单片原子提交并生成SHA256，最终任务清单引用所有分片。旧只读实验不新增混入其原清单的分析文件。

部署目录仍在数据盘同一研究根下，旧版本进入archive，v2使用新活动目录。正式发布包不携带重复的大量本地验证模型副本；历史证据不删除。

50GB盘先按10000局样本测量压缩后bytes/game、额外Tensor量和写入速度，再外推整次预算；不预言全量详细牌谱只占几十MB。预留磁盘下限，达到下限安全停机并提交已有完整分片，不能静默丢牌谱。大规模实验可能需扩盘/外部归档，费用另批。

## 9. 评估与方法选择

### 9.1 指标与分母

主指标是原始平均净分与连续会话累计净分。辅助报告胡牌率、自摸率、接炮胡率、点炮率、平均点炮损失、被自摸损失、承包事件/损失、牌型/倍数分布、正常流局与异常截断。正常流局率分母为所有实际对局，不能混入程序超时或MAX_DECISIONS。

胡牌率根据winner身份，而不是通用地用score>0；含其他独立结算时两者可能不同。点炮率按candidate为实际放炮者定义，同时可另报每次弃牌机会的点炮事件率。承包者、放炮者、付款者分开存储，不混成一个payer。

尾部指标使用明确的下尾净分CVaR-5%（最差5%净分平均，越大越好），另报负分损失口径，避免符号混淆。风险改进需与收益一同比较，不奖励彻底弃胡带来的表面低点炮率。

### 9.2 测试集合

使用新规则新基线：随机合法策略、规则启发式、同对手条件下的启发式自对战、旧快照/不同风格对手池。旧6个模型只保留旧环境诊断，不为它们编造新34种牌观察的兼容映射。

固定牌墙与四座位轮换继续用于受控单手比较；连续玩法按会话为单位轮换候选初始座位，庄家后续随实际结果变化。不能每手重置n和已亮马来人为对称化真正玩法。

随机源按语义分开：实际手局墙、专门开马、策略动作、对手选择和评估。方法间共享外生牌序安排以降方差，但行为导致的牌路、连庄和取马分支不同属于策略效果，不强行使它们相同。

建议先使用1000墙×4座位做诊断，再固定5000墙×4，正式最多25000墙×4=每模型100000局；连续会话与稀有局面另设样本数和预算。独立训练种子首轮3个、关键结论目标5个；更大的评估样本不能替代更多训练种子。[R5]

已反复检查过的旧5000墙仅作开发回归，不继续当作新研究最终盲测。训练、开发、最终评估的随机键空间隔离。按牌墙组或连续会话聚类的配对置信区间，不能把四座位或同桌四家当成独立样本。

### 9.3 最小实验矩阵

先得到完整规则下可用的公开历史Critic + Recurrent PPO基线。第一项受控比较仅改变多路线/动作资格表示，网络容量与辅助特征预算明确报告。此后再对最有希望的表示分别检验风险辅助头和历史+特权Critic，避免同时改变所有因素后把收益归给一个模块。

任何改进均在固定有效Actor样本预算、匹配对手配置、相同评估集下比較；同时报告原始整局数、环境动作数、优化器步数、墙钟和计算精度。以相同小时预算做的实验只能支持计算效率比较，不自动支持样本效率优势。

不能预先保证Privileged胜过Plain，也不能为了“优秀”只展示最好种子。出现收益/风险权衡时给出带置信区间的曲线，不把风险更低但平均收益明显下降自动判为更强。

## 10. 长任务与运行体验

新的启动器在创建任务目录和改写当前指针之前，先检查研究根任务锁与设备占用。已存在同一活任务时返回原job_id和状态，而不是新建一个马上失败的重复任务。控制命令使用精确job_id，禁止用最新目录推断应恢复哪次任务。

任务目录记录根PID、启动时间、进程树、参与版本与设备。独占检查允许同一任务登记的进程，不因多worker误判为外部污染；不识别的GPU任务则暂停/拒绝启动，不自动杀死无关进程。

设置有效样本目标、总墙钟上限、评估预算、磁盘下限。7.5小时明确解释为整次任务预算还是训练时间，不再用“训练7.5小时后还有无限评估”替代总预算。时间不足时保存状态并标记训练/评估尚未完成，不伪造completed。

分钟级进度应区分已启动、采样、更新、结算等待、评估、保存、暂停和失败；CPU TIME增加不是学习有效性的证明。无需每次手工写上百行shell脚本，交付可上传的已校验工具，示例只使用少量短命令。

Checkpoint按一致性提交点保存Actor/Critic/优化器、各桌状态、各座位记忆、随机源、对手池版本、未结账单、分片提交游标和预算计数。新并行机制须测试正常暂停、强制中断、重复恢复和旧锁残留；与不中断轨迹的一致性测试以声明的确定性模式完成。生产模式不能仅凭旧A04小MLP通过就承诺完全无损恢复。

### 11.1 短试到长跑

CPU规则与回放测试 → 新GPU核心算子短验 → 10分钟端到端采样与存储测量 → 30～60分钟新规则学习短试 → 多种子小预算筛选 → 经过确认的长任务。

各阶段样本量是验收计划：例如先10000局随机合法回放压力验收；不能用随机覆盖替代稀有牌型、承包和跨局边界的明确构造案例。正式长任务时长与费用根据新环境实测和用户预算确定，不承诺旧7.5小时即可训练到优秀或完成论文。

## 12. 论文定位与裁决

现阶段没有证明某个新算法有效，也不能保证CCF-B录用。研究主线候选为：在无人类示范的多人不完全信息博弈中，动作对多种组合目标资格的不可逆影响，能否用显式表示改善净收益、风险与样本效率。

跨局开马、公开留手和延迟责任提供较有特色的实验场景，但新房规或新日志系统本身不自动是算法创新。PPO、特权Critic和批量采样已有前人工作，作为基础方法与工程，不包装成原创。[R1-R4]

优先证明一个方法假设，配套正确环境、强基线、消融、全局牌谱与统计不确定性。旧RGRC/LACC名称不作为已完成或必须同时实现的贡献；需要时再依据明确方法定义纳入独立实验。
